# LLE 다이스 마스터 (Dice Master) 역기획서

본 문서는 LLE 엔진에서 구현된 '주사위 예측 게임(V28)'의 구조를 역으로 분석하여, 다른 AI나 개발자가 동일한 수준의 게임을 빠르게 재현할 수 있도록 작성된 표준 기획 사양서입니다.

---

## 1. 게임 개요 (Overview)
*   **게임명:** 다이스 마스터 (Dice Master)
*   **장르:** 확률 기반 베팅 시뮬레이션
*   **핵심 루프:** 로비(자원 관리) → 베팅(예측) → 결과(판정) → 정산(보상) → 리포트(최종 성적)
*   **주요 특징:** 
    *   d6(6면체 주사위) 기반의 High/Low 예측 시스템.
    *   주사위 자원 소모 및 무한 리필 경제 구조.
    *   실시간 누적 승률 트래킹 및 리소스 모니터링.

---

## 2. 시스템 구조 (System Architecture)

### 2.1 자원 및 변수 (Variables)
| 변수명 | 타입 | 초기값 | 설명 |
| :--- | :--- | :--- | :--- |
| `gold` | Number | 0 | 플레이어의 보유 자산 |
| `dice` | Number | 10 | 현재 보유한 주사위 수 (판당 -1 소모) |
| `total_games` | Number | 0 | 전체 플레이 횟수 |
| `total_wins` | Number | 0 | 승리(예측 성공) 횟수 |
| `win_rate` | Number | 0 | 누적 승률 (계산식: `total_wins * 100 / total_games`) |
| `roll` | Number | 0 | 주사위 굴림 결과값 (1~6) |
| `bet_high` | Number | -1 | 유저 선택 (1: 높음, 0: 낮음) |

### 2.2 핵심 게임 로직 (Core Logic)
1.  **안전 시작 시퀀스:** 
    *   `Entry` 노드에서 수식 없이 입장 버튼만 노출하여 엔진 초기화 에러 방지.
    *   `Trigger` 노드에서 모든 전역 변수 강제 초기화.
2.  **판정 알고리즘:**
    *   **높음(High):** `roll >= 4` (성공 확률 50%)
    *   **낮음(Low):** `roll <= 3` (성공 확률 50%)
3.  **자원 소모 및 종료 조건:**
    *   매 라운드 시작 시 `dice - 1` 수행.
    *   `dice == 0`인 상태에서 라운드 진입 시 즉시 **최종 리포트**로 강제 이동.

## 3. UI/UX 디자인 사양 (UI Specification)

### 3.1 레이아웃 원칙 (Layout Rules)
*   **수직 중앙 정렬:** `VStack` 내부에 3개의 `Spacer`를 배치하여 콘텐츠가 화면 중앙에 오도록 설계.
*   **양끝 배치 (Edge-to-Edge):** 상단 리소스 바와 하단 상태 바는 `HStack`과 `Spacer`를 조합하여 화면 끝에 밀착.
*   **화이트 빅 버튼:** 주요 인터랙션 버튼은 `secondary` (White) 변색을 사용하고 큼직하게 배치.

### 3.2 주요 화면 구성
*   **로비:** 현재 주사위 잔량 표시 및 '10개 충전' 버튼 제공.
*   **베팅 화면:** 
    *   상단: 골드/주사위 원형 계기판.
    *   중앙: 높음 버튼 - 팁 텍스트 - 낮음 버튼 (수직 배치).
    *   하단: 성공률 및 누적 플레이 횟수.
*   **결과 화면 (승패 분리):** 승리와 패배를 각각 다른 노드로 구성하여 UI 겹침 방지.

## 4. 엔진 구현 가이드 (Technical Implementation)

### 4.1 SDT (마찰 점수) 필수 삽입
모든 `Choice` 및 `Reward` 노드에는 아래의 SDT 객체를 포함하여 시뮬레이터의 안정성을 보장해야 함.
*   `autonomy`: 0~10
*   `competence`: 승리 시 +20 / 기본 +5
*   `motivation`: 승리 시 +30 / 베팅 시 +20

### 4.2 엣지(Edge) 연결 패턴
*   **루프 구조:** 정산 완료 후 `dice > 0` 게이트를 통해 다시 베팅 화면으로 순환.
*   **데이터 업데이트:** `Trigger` 노드를 활용해 판정 직후 변수를 즉시 업데이트하여 MockSpec에 실시간 반영.
