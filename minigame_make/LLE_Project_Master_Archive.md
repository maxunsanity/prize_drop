# LLE Project Development & Maintenance Archive

본 문서는 LLE 엔진을 활용한 프로젝트 개발 과정에서 발견된 주요 기술적 이슈, 해결 방안 및 프로젝트 이력을 기록한 공식 아카이브입니다.

---

## 1. LLE 엔진 핵심 기술 노하우 (Technical Know-how)

### ⚠️ [중요] 변수명 및 ID 내 하이픈(-) 사용 금지
*   **이슈:** 노드 ID나 변수명에 하이픈(예: `node-1`) 사용 시 수식 파싱 오류 발생.
*   **원인:** 엔진 내부에서 `-`를 산술 연산자(Minus)로 인식하여 오작동 유발.
*   **해결:** 모든 식별자에는 언더바(`_`)를 사용함. (예: `node_1`, `money_gain`)

### 📦 [필수] 글로벌 변수 초기화 (n-init)
*   **이슈:** 시뮬레이션 중 "Unknown Name" 에러 발생.
*   **원인:** 특정 노드에서 참조하는 변수가 런타임 이전에 정의되지 않음.
*   **해결:** `Entry` 노드 직후에 `n-init` 트리거 노드를 배치하고, 프로젝트에서 사용하는 모든 변수의 초기값을 명시적으로 선언함.

### ⚖️ [규칙] 게이트(Gate) 노드의 분기 처리
*   **이슈:** 게이트 노드 연결 시 엔진 유효성 검사 실패.
*   **원인:** 게이트 노드의 출력 엣지가 2개(True, False) 미만인 경우.
*   **해결:** 게이트 노드는 반드시 **참(True)** 경로와 **거짓(False)** 경로를 모두 연결해야 함. 단방향 흐름이 필요한 경우 `Trigger` 노드로 대체하여 사용함.

### 🏰 [최신] 안전한 시작 시퀀스 (Safe Startup Sequence)
*   **이슈:** `Entry` 노드에서 변수 호출 시 "Unknown Name" 에러 발생.
*   **원인:** `Entry` 노드는 엔진의 변수 초기화 트리거보다 먼저 렌더링될 수 있음.
*   **해결:** `Entry`(순수 비주얼) -> `Setup`(데이터 초기화 트리거) -> `Lobby`(변수 사용 초이스) 순서로 구성하여, 화면에 변수가 보이기 전 완벽한 데이터 로딩을 보장함.

### 🎭 [비법] 물리적 화면 분리 (Physical Node Splitting)
*   **이슈:** 조건부 렌더링(`on.visible.condition`) 사용 시 UI 요소가 겹쳐 보이는 현상.
*   **해결:** 승리(`n_ui_success`)와 패배(`n_ui_fail`) 화면을 별도의 노드로 분리하여 물리적으로 겹침을 방지하고, 명확한 유저 경험을 제공함.

### 🧪 [필수] 마찰 점수(SDT) 연동 및 4대 필드
*   **이슈:** 보상 획득이나 특정 루프 구간에서 시뮬레이터가 응답하지 않음.
*   **해결:** 모든 상호작용 노드(`Choice`, `Reward`)에 SDT 속성 4가지(`autonomy`, `competence`, `relatedness`, `motivation`)를 명시적으로 모두 포함해야 함. 특히 `motivation` 누락 시 시뮬레이터가 멈추므로 주의.

### 🔄 [규칙] 자원 조작 및 주사위 차감 구조
*   **이슈:** 자원이 실제 UI 게이지에 반영되지 않거나 조건문이 무한 루프에 빠짐.
*   **해결:** 
    *   `disposal` 노드 사용 후 반드시 `trigger` 노드에서 변수를 직접 차감해야 함. (예: `dice = dice - 1`)
    *   자원(`resource`) 노드에 -1을 직접 연결하는 것은 금지.
    *   라운드 시작 시 사용하는 임시 변수(`money_gain` 등)는 반드시 매번 0으로 리셋.

### 🖥️ [구조] Choice 노드와 Scene 노드의 UI 활용
*   **이슈:** 분기 선택이나 팝업 화면 구성의 혼선.
*   **해결:** 
    *   `Choice` 노드는 단순 선택지가 아니라 화면(UI) 역할도 담당함. `targetNodeId`를 활용하여 화면 전환을 구성.
    *   모달 팝업은 `Scene` 노드의 `Modal` 컴포넌트로 구현하며, 반드시 출력 엣지를 연결하여 시뮬레이션 종료를 막을 것.

### 🔗 [규칙] 엣지 연결 및 핸들 방향
*   **이슈:** 엣지 렌더링 시각적 버그 발생.
*   **해결:** 같은 노드로 2개 이상의 엣지가 들어올 때 반드시 서로 다른 방향의 입구를 지정할 것. (예: 일반 흐름은 Bottom -> Top, 루프 복귀는 Bottom -> Left)

### ⚖️ [디자인] 수직 중앙 정렬 & 양끝 배치
*   **이슈:** UI 요소가 상단에 쏠리거나 썰렁해 보이는 문제.
*   **해결:** 
    *   `VStack` 내부에 **3단계 스페이서(Top, Middle, Bottom)**를 사용하여 콘텐츠를 화면 정중앙에 배치.
    *   `HStack` 내부에 `Spacer`를 넣어 리소스 정보를 좌측 끝과 우측 끝으로 밀어내어 시각적 균형 확보.

## 2. 프로젝트 개발 이력 (Project History)

### 🎲 주사위 예측 게임 (Dice Betting Game)
*   **최종 버전:** **V28 (Full-Pack UI Edition)**
*   **주요 사항:** 
    *   로비-베팅-정산-리포트로 이어지는 완벽한 게임 경제 루프 구현.
    *   무한 리필 시스템 및 누적 성공률 트래킹 탑재.
    *   화이트 빅 버튼 수직 배치 및 SDT 완벽 연동.

### 🦖 공룡 달리기 미니게임 (Dino Run)
*   **최종 버전:** **V5 (Optimization Completed)**
*   **주요 사항:** 장애물 타입별 비주얼 분기(`type_gate`) 적용 및 충돌 시 즉시 종료(One-Shot Death) 로직 안정화.

### ⚔️ 턴제 전투 시스템 (RPG Battle System)
*   **현재 상태:** **V1 (Prototyping)**
*   **주요 사항:** HP 시스템 연동 및 주사위 기반(2d6) 데미지 산출 공식 적용.
