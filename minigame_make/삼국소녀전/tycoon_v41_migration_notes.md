# 🚀 Tycoon 시뮬레이션 엔진 최적화 마스터 가이드 (V41 베이스 복구용)

본 문서는 이전 작업에서 발생한 모든 엔진 오류(Unknown Name, 시뮬레이션 멈춤 등)의 원인을 분석하고, 성공적인 우회/해결 전략을 기록하여 다음 V41 베이스 작업 시 동일한 실수를 반복하지 않기 위한 **절대 가이드라인**입니다.

---

## ✅ 1. 완벽하게 작동했던 것 (유지해야 할 필수 로직)

1. **보상 허브(n-accumulate-tile)의 '1원 보정' 우회:**
   * **원인:** 보상 허브는 `money_gain`이 0이거나 없을 때 강제로 1원으로 보정하는 로직이 있습니다.
   * **성공 해결책:** 돈 보상이 발생하지 않는 이벤트(복불복 주사위 획득, GO타일 미통과, 감옥 탈출 성공)의 출력 엣지(`Target`)는 보상 허브를 거치지 않고 **반드시 `n-loop-gate`로 직행**해야 합니다.
2. **단일 스테이지 개체 (V41 기본 구조):**
   * 구조가 가장 깔끔하고 에러가 없었던 상태. 단, 배율 동적 변경이 안 되는 한계가 있었습니다.

---

## ❌ 2. 절대 하면 안 되는 것 (엔진의 숨겨진 함정들)

1. **데이터 선(Data Edge) 수식에 변수 사용 금지 (`stage_id + 1`)**
   * 엔진은 시뮬레이션 도중 데이터 선의 행 번호를 실시간 변수로 재계산하지 않습니다.
2. **트리거 내장 함수 조작 금지 (`table.load()`)**
   * LLE 트리거에는 테이블을 강제로 새로고침하는 내장 함수가 존재하지 않습니다.
3. **수식 내 하이픈(-) 포함 개체명 참조 절대 금지 🚨**
   * **치명적 오류:** 개체 ID가 `node-entity-stage_1`일 때, 수식에 `node-entity-stage_1.reward_scale`을 적으면 엔진이 하이픈을 **빼기(Minus) 연산자**로 해석하여 **"Unknown Name 'node'"** 에러를 발생시킵니다.
   * **해결책:** 엔진은 개체 참조 시 접두사를 무시합니다. 수식에서는 반드시 `stage_1.reward_scale` 형태로만 사용해야 합니다.
4. **글로벌 변수의 맹신 금지 (`n-init` 누락)**
   * 게이트(Gate) 노드에서 조건(예: `stage_id == 1`)을 평가할 때, 해당 변수가 장부(글로벌 속성)에만 있고 **초기화 트리거(`n-init`)**에 명시적으로 선언되지 않으면 "Unknown Name" 에러가 발생합니다.

---

## 🛑 3. 시뮬레이션 급정거(멈춤) 원인과 해결책

1. **유령 타일 참조 오류 (감옥, 세금 등)**
   * `tile_jail.tax_fixed_value` 처럼 개체 노드가 없거나 이름이 꼬인 상태로 수식을 참조하면 즉시 멈춥니다.
   * **해결책:** 특수 타일의 수치는 개체를 통하지 않고, `n-init`에서 글로벌 변수(`jail_fine`, `tax_low_value` 등)로 직접 선언하여 사용합니다.
2. **동기 부여(Motivation) 0에 의한 파업**
   * 세금, 감옥 징수 시 노드의 `sdtEffects`에 동기(Motivation) 마이너스 수치가 있으면, 플레이어 멘탈이 0이 되어 시뮬레이션이 강제 종료됩니다.
   * **해결책:** 모든 노드의 부정적 `sdtEffects`를 0으로 고정하고, `n-init`에서 초기 `motivation`을 1000 이상으로 넉넉하게 부여합니다.

## 🗺️ 4. 다음 작업 (V41 베이스) 마스터 플랜

다음 작업 시 V41 파일에서 아래 순서대로 **'개체 없는 초심플 스테이지(Zero-Entity)'** 전략을 적용합니다.

### 📍 [1단계] 기초 공사 (변수 및 멘탈 세팅)
* `n-init` 노드에 모든 스테이지 변수(`current_stage_scale` 등)와 특수 타일 변수(`jail_fine`, `tax_low_value` 등)를 값과 함께 일괄 등록.
* `n-init` 노드에 `motivation: 1000` 설정 및 모든 노드의 `sdtEffects` 마이너스 수치 제거.
* 수식 내의 유령 타일 참조(`tile_jail.xxx`)를 방금 등록한 글로벌 변수로 일괄 교체.

### 📍 [2단계] 허브 우회 (1원 좀도둑 박멸)
* 감옥 성공(`n-jail-success`), 복불복 주사위(`n-chance-dice-logic`), GO 실패(`n-go-gate` false) 엣지를 `n-loop-gate`로 직결.

### 📍 [3단계] "Zero-Entity" 스테이지 동기화 (에러율 0% 로직)
1. 기존 단일 스테이지 개체(`node-entity-stage`) 완전 삭제.
2. `n-roll` (주사위 굴리기) 노드 직후에 **스테이지 확인 게이트 체인(`stage_id == 1`, `== 2` ...)** 연결.
3. 각 게이트 참(True) 분기에 **하드코딩 트리거** 연결.
   * *예: 1단계 통과 시 트리거에 `current_stage_scale = 1.0` 직접 대입.*
4. 트리거 출력을 다시 기존 이동 로직(`n-move-logic`)으로 연결.

**결론:** 데이터 테이블에 의존하지 않고, 변수에 수치를 직접 때려 박는 **Zero-Entity 하드코딩 방식**이 현재 엔진 환경에서 가장 강력하고 멈춤 없는 무결점 해결책입니다.
