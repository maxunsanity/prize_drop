이벤트 구조

5단계로 구성된 발굴형 솔로 이벤트다. 각 단계마다 새로운 게임판(그리드)이 주어지며, 곡괭이를 소모해 타일을 하나씩 공개한다. 숨겨진 보석을 모두 찾으면 단계 클리어 보상이 지급되고 다음 단계로 진행한다. 5단계를 모두 클리어하면 All-Star 최종 보상이 지급되고 이벤트가 종료된다.

지뢰찾기와 구조는 유사하지만 "패배" 개념이 없다 — 곡괭이가 소진되면 플레이가 멈추고 레벨 클리어로 곡괭이를 보충하면 이어서 진행할 수 있다. 단계가 올라갈수록 그리드가 커지고 보석 수가 늘어나며 맵 형태도 다양해진다.

구분내용
단계 수5단계
단계 클리어 조건해당 단계의 보석 전부 수집
최종 보상5단계 전부 클리어 시 All-Star 보상 지급

코어 펀

무엇이 숨어 있는지 모르는 탐색의 긴장감이 핵심이다. 곡괭이를 탭할 때마다 보석이 나올지 빈칸일지 알 수 없는 불확실성이 반복 플레이를 유도한다. 빈칸에서도 소량 보상이 나올 수 있어 "어디서든 뭔가 나온다"는 기대감을 유지한다. 발굴 아이템이 여러 칸을 차지하고 있어 인접 칸을 팔 때의 연결 발견 재미도 있다. 단계가 올라갈수록 맵 형태가 바뀌는 점진적 볼거리가 완주 동기를 만든다.

2. 타일 타입 정의

Hidden Temple의 런타임 타일은 5종류다. TRAP은 없다 — Royal Match 레퍼런스 기준으로 트랩/페널티 타일은 존재하지 않으며, 삼국소녀전 GO에서도 동일하게 적용한다.

타입Enum배치 주체설명
보석GEM서버 런타임 랜덤수집 목표. 발굴 시 collected_gems +1
발굴 아이템ITEM서버 런타임 랜덤멀티칸 아이템. 같은 item_instance_id 칸 전부 공개 시 보상 지급
소량 보상 빈칸EMPTY_REWARD서버 런타임 랜덤소량 엽전/주사위 즉시 지급. 허탈감 방지
순수 빈칸EMPTY서버 런타임 (나머지)아무것도 없음. 먼지 이펙트만 재생
설계 의도: 빈칸을 파도 15% 확률로 소량 보상이 나오게 해 곡괭이를 쓰는 행위 자체에 부정적 경험이 쌓이지 않도록 한다. 발굴 아이템은 인접 칸이 연결될 때의 발견 재미를 주는 중간 목표 역할을 한다.

타일 배치 원칙

  • 게임판 전체 타일 배치는 서버에서 스테이지 진입 시 런타임 생성 (기획자 정의 BLOCK/BOX 구조 기반)
  • 클라이언트는 타일 탭 시 서버에 요청 → 서버가 해당 타일 결과 반환
  • 치팅 방지: 클라이언트는 공개된 타일 결과만 알 수 있으며 미공개 타일 정보는 서버에서만 보유

→ 전제 조건: pickaxe_count > 0

8. 스테이지 맵 시스템

8-1. 설계 원칙

기획자 / 서버 역할 분리

구분담당내용
기획자엑셀 작성BLOCK / BOX / NULL 배치 정의, 발굴 아이템 슬롯 지정
서버 런타임개발팀 구현발굴 아이템 랜덤 배치, GEM 랜덤 배치, EMPTY_REWARD 랜덤 배치

기획자는 맵의 형태(BLOCK/BOX/NULL)와 어떤 아이템이 숨겨지는지만 정의한다. 실제 배치 위치는 서버가 매 진입 시 랜덤으로 결정한다. 플레이어가 스테이지를 외울 수 없는 구조가 된다.

그리드 판정 규칙 (우선순위 순)

  1. col 또는 row 중 하나라도 NULL → 해당 칸은 존재하지 않음 (렌더링 안 함)
  1. col 또는 row 중 하나라도 BLOCK → BLOCK (발굴 불가)
  1. col도 BOX AND row도 BOX → BOX (발굴 가능)

NULL을 활용하면 직사각형이 아닌 마름모, 십자, ㄷ자 등 자유로운 맵 형태 구성이 가능하다.

런타임 배치 흐름

[스테이지 진입]
ht_stage_config 로드
→ col_1~10 / row_1~10 교차 판정으로 BOX 칸 목록 추출
→ item_slot_1~3에 지정된 아이템 shape 확인
→ BOX 공간 내 충돌 없이 아이템 랜덤 배치 (개발팀 구현)
→ 남은 BOX 칸 중 gem_count개 랜덤 GEM 배치
→ 남은 BOX 칸 중 empty_reward_ratio(15%) EMPTY_REWARD 배치
→ 나머지 → EMPTY

[배치 불가 에러 처리 — 개발팀 구현]
- BOX 칸 수 < 아이템 전체 점유 칸 합산 → 배치 불가 에러 반환
- 아이템 겹침 / BLOCK·NULL 칸 침범 시 → 재시도 (최대 100회)
- 100회 초과 실패 시 → config 오류 로그 + 기획팀 Slack 알림
- gem_count > 남은 BOX 칸 수 → 배치 불가 에러
