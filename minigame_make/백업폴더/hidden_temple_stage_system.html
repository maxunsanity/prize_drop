값의미렌더링발굴 가능
NULL 칸 자체가 없음 — 그리드 외부 영역 투명 (빈 공간) —
BLOCK 칸은 있지만 파괴 불가 진한 갈색 블록 ✕
BOX 발굴 가능한 칸 중간 갈색 블록 ✓
그리드 최종 타입 판정 규칙 (우선순위 순)
1
col 또는 row 중 하나라도 NULL → 해당 칸 없음 (렌더링 안 함)
2
col 또는 row 중 하나라도 BLOCK → BLOCK (발굴 불가)
3
col도 BOX AND row도 BOX → BOX (발굴 가능)
NULL로 만드는 맵 형태 예시
col/row에 NULL을 넣으면 직사각형이 아닌 자유로운 형태 구성 가능

런타임 흐름 + 에러 처리
서버 런타임 배치 흐름
1
스테이지 진입 — ht_stage_config 로드. col/row 교차 판정으로 NULL/BLOCK/BOX 결정
2
아이템 배치 — item_slot_1~3 shape 확인. BOX 공간 내 충돌 없이 랜덤 배치 (개발팀 구현)
3
GEM 배치 — 남은 BOX 칸 중 gem_count개 랜덤 선택 → GEM 지정
4
EMPTY_REWARD 배치 — 남은 BOX 칸 중 15% 랜덤 → EMPTY_REWARD 지정
5
EMPTY 처리 — 나머지 BOX 칸 전부 → EMPTY
6
board_state 저장 — 완성 배치 서버 저장. 플레이어 탭 시 서버 요청 → 결과 수신
⚠️ 에러 처리 조건 (개발팀 전달)
❶ BOX 칸 수 < 아이템 점유 칸 합 → 배치 불가 에러. 스테이지 진입 차단
❷ gem_count > 남은 BOX 칸 수 → 배치 불가 에러
❸ 아이템 겹침 / BLOCK·NULL 칸 침범 → 재시도 (최대 100회)
❹ 100회 초과 실패 → config 오류 로그 + 기획팀 Slack 알림
💡 기획자 작성 시 주의사항
BOX 칸 수 ≥ (아이템 점유 합 + gem_count) 확인 필요
NULL 활용 시 아이템이 NULL 칸에 걸치지 않도록 BOX 구역 연속성 확인
엑셀 작성 후 컨버터 스크립트 사전 검증 권장
