# 📘 LLE 학습 가이드 — 엔진 규칙 & 오류 없는 작업 경험

> LLE 엔진을 사용하면서 실제 작업을 통해 검증된 규칙과 오류 패턴을 정리한 학습 가이드입니다.
> 

---

# 1. 플로우 시작 구조 — 반드시 이 순서

```
entry(진입) → trigger(게임 설정) → choice(첫 화면)
```

entry 노드에서 변수를 바로 쓰면 **Unknown Name 오류** 발생.

반드시 trigger 초기화 노드에서 모든 변수를 먼저 선언한 뒤 사용할 것.

**게임 설정 trigger 필수 선언 항목:**

```
gold = 0          기본 자원
dice = 10         주사위 수량
bet_high = -1     베팅 선택값 (미선택 상태)
roll = 0          주사위 굴림 결과 (판정 전 기본값)
money_gain = 0    이번 라운드 획득량 (복잡한 보상 계산 시)
```

통계 추가 시 함께 선언:

```jsx
total_games = 0   전체 게임 횟수
total_wins = 0    승리 횟수
win_rate = 0      누적 승률
```

# 2. 노드 ID 규칙 — 하이픈(-) 절대 금지

- ❌ `n-init`, `n-gate-dice`, `node-1`
- ✅ `n_init`, `n_gate_dice`, `node_1`

LLE 엔진이 하이픈(-)을 빼기 연산자로 인식하여 수식 파싱 오류 발생.

gate/trigger 조건식에서 특히 위험.

---

# 3. gate 노드 — true/false 양방향 연결 필수

gate 노드는 반드시 true/false 양방향을 모두 연결해야 합니다.

한쪽만 연결하면 LLE 유효성 검사 실패.

단방향 분기가 필요하면 gate 대신 trigger를 사용하세요.

**표준 gate 조건 패턴:**

```
dice > 0                                          주사위 잔량 확인
(bet_high == 1 && roll >= 4) || (bet_high == 0 && roll <= 3)    베팅 판정
enemy_hp <= 0                                     적 사망 확인
player_level == 1                                 레벨 분기
is_boss == 1                                      보스 여부 분기
kill_count >= 3                                   킬카운트 체크
```

# 4. SDT — 4개 필드 전부 명시

```json
"sdtEffects": {
  "autonomy": 0,
  "competence": 5,
  "relatedness": 0,
  "motivation": 20
}
```

choice, reward 노드에 반드시 포함.

**motivation 누락 시 시뮬레이터가 중간에 멈춥니다.**

gate 노드는 `frictionScore = 0` 명시 필수.

권장 수치:

- 베팅/선택: autonomy 5, motivation 20
- 승리 보상: competence 20, motivation 30
- 그 외 노드: 모두 0

# 5. 자원(Resource) 시스템 — 핵심 규칙

## 연결 가능한 조합

```
소비: resource 노드(left) → disposal 노드(right)
획득: reward 노드(right) → resource 노드(left)
```

## 연결 불가능한 조합

- trigger → resource: 규칙 위반 (엔진 오류)
- success → resource: 구조적으로 불가
- resource → resource: 불가

## resource 노드 중복 금지

같은 resourceKey를 가진 resource 노드는 플로우 전체에서 **1개만** 허용.

오류: `유저 식별자 경로가 중복됩니다(자원 key 또는 entityKey.속성). 중복: gold`

## resourceAmountExpression 타입 주의

- ❌ 잘못된 방식: `"resourceAmountExpression": 1` (숫자)
- ✅ 올바른 방식: `"resourceAmountExpression": "1"` (문자열)

오류: `t?.trim is not a function`

## resourceId 프로젝트 종속

resource 노드의 resourceId는 현재 LLE 프로젝트에서 생성한 자원 ID와 일치해야 합니다.

**프로젝트마다 ID가 다릅니다.** 해당 프로젝트에서 직접 export한 resource 노드를 기준으로 사용할 것.

## 골드 변수 vs 재화 게이지

`gold = gold + 1` trigger는 변수만 증가하고 우측 패널 게이지에는 반영 안 됩니다.

우측 패널 게이지 연동에는 **reward → resource 노드 연결이 필수**입니다.

---

# 6. success 노드는 플로우 종료

`success` 노드는 플로우를 종료하는 노드라 다음 노드로 연결이 실행되지 않습니다.

보상 후 종료가 필요하면:

```
승리(reward, right) → resource(골드)    [우측 resource 연결]
승리(reward, bottom) → 종료(success)   [하단 success 연결]
```

---

# 7. 엣지 연결 규칙 — 핸들 방향

**엣지 ID 형식:**

```
xy-edge__{source노드ID}{sourceHandle}-{target노드ID}{targetHandle}
gate 분기: 끝에 -true 또는 -false 추가
```

**표준 핸들 방향:**

- 일반 흐름 (위→아래): bottom → top
- gate false 분기 (오른쪽): right → left
- 루프 복귀 (아래→왼쪽): bottom → left
- 여러 선이 같은 노드로 들어올 때: 입구 방향 반드시 다르게 지정

같은 targetHandle에 2개 이상 연결하면 시각적 버그 발생.

---

# 8. choice 노드 = UI 화면 + 분기

choice 노드는 단순 선택지가 아니라 화면(UI) 역할도 합니다.

mockSpec의 Button에 targetNodeId를 지정하면 버튼 클릭 시 해당 노드로 이동합니다.

**주의:** targetNodeId와 실제 엣지의 target이 반드시 일치해야 합니다. 불일치 시 종료됩니다.

승리/패배 화면은 반드시 별도 choice 노드로 물리적으로 분리하세요. 같은 노드에서 조건부 렌더링하면 UI가 겹쳐 보입니다.

---

# 9. 모달 팝업 — scene 노드

scene 노드의 mockSpec에서 Modal 컴포넌트를 사용합니다.

`{{변수명}}` 형식으로 현재 값을 화면에 표시할 수 있습니다.

**scene 노드는 반드시 출력 엣지를 연결해야 합니다.** 없으면 그 자리에서 종료됩니다.

# 10. 주사위 소비 구조 — disposal + resource 조합

```
gate(dice > 0) [true]
    ↓
disposal(주사위 소비) ←[resource, amount:1]← resource(주사위)
    ↓
다음 노드
```

trigger에서 `dice = dice - 1`로 직접 차감하면 우측 패널 게이지가 업데이트되지 않습니다.

반드시 disposal + resource 노드 조합을 사용하세요.

---

# 11. damage 변수 — 노드 분리 필수

같은 trigger 안에서 변수를 선언하고 즉시 그 변수를 다른 계산에 쓰면 오류가 발생합니다.

- ❌ `enemy_hp = enemy_hp - (player_atk + rand.d6())`
- ✅ [굴림 노드] `damage = player_atk + rand.d6()` → [적용 노드] `enemy_hp = enemy_hp - damage`

---

# 12. 엔티티(entity) 참조 — 타입별 제한

**number 타입:** 엔티티 참조 가능

```
player_atk = character.atk    ✅
enemy_hp = goblin.hp          ✅
```

**string 타입:** 엔티티 참조 불가

```
enemy_name = goblin.name      ❌ (작동 안 함)
enemy_name = "고블린"           ✅ (직접 입력 필요)
```

---

# 13. 레벨업 exp_to_next 주의

레벨업 시 exp_to_next는 **현재 레벨이 아닌 다음 레벨**의 값을 참조해야 합니다.

```
레벨1→2 레벨업 시: exp_to_next = levelup_2.exp_to_next
레벨2→3 레벨업 시: exp_to_next = levelup_3.exp_to_next
```

같은 레벨의 exp_to_next를 참조하면 다음 레벨업 목표가 갱신되지 않습니다.

---

# 14. 통계 트래킹 공식

```
win_rate = total_wins * 100 / total_games
```

업데이트 위치:

- 높음/낮음 선택 trigger: `total_games = total_games + 1`
- 승리 trigger: `total_wins = total_wins + 1`
- 판정 후 trigger: `win_rate = total_wins * 100 / total_games`

total_games가 0일 때 나누기 오류 발생 가능. 첫 라운드 이후부터 계산하도록 구성할 것.

---

# 15. 메모 노드

메모 노드는 플로우 로직에 영향을 주지 않는 스티커 노트입니다.

`label` = 제목, `description` = 내용으로 분리해야 합니다.

label에 모든 글을 넣으면 제목 영역에만 표시됩니다.

# 16. 검증된 최소 플로우 구조

```
n_entry
→ n_init (trigger: 게임 설정)
→ n_lobby (choice: 로비)
   → n_refill (trigger: dice+10) → n_lobby (루프)
   → n_gate_dice (gate: dice > 0)
      → [false] n_end (success: 게임 종료)
      → [true]  n_disposal (disposal) ←[resource]← n_res_dice
                → n_bet (choice: 베팅)
                   → n_high (trigger: bet_high=1, roll=rand.d6())
                   → n_low  (trigger: bet_high=0, roll=rand.d6())
                   → n_judge (gate: 판정 조건)
                      → [true]  n_win (reward, right) → resource(골드)
                                     ↓ (bottom)
                                n_next (choice: 다음 라운드) → n_gate_dice (루프)
                      → [false] n_lose (failure) → n_next
```

참조 파일:

- 주사위_게임_쉬운버전.json (노드 20개 / 엣지 19개)
- 주사위_게임_어려운버전.json (노드 26개 / 엣지 24개)
- 전투_3단계.json (노드 56개 / 엣지 49개)

# 17. 최신 V54+ 마이그레이션 및 Mockup 이식 (2026-04-29)

> 초기 LLE 작업물이나 구형 버전(V40대 이하)을 최신 규격으로 업그레이드하고, 엔진 내장 UI(Mockup)를 이식하는 실무 노하우입니다.

## 🏗️ V54+ 표준 마이그레이션 규칙
1. **motivation 필수 주입**: 최신 시뮬레이터는 `motivation` 값이 없으면 엔진이 멈춥니다. `n-init` 노드에 반드시 초기값(예: 1000)을 선언해야 합니다.
2. **SDT 음수(-) 클리닝**: 구형 파일의 `sdtEffects`에 마이너스 수치가 있으면 밸런스 오류가 발생합니다. 모든 감정 수치는 0 이상으로 보정해야 합니다.
3. **리소스 간소화**: `gold`, `exp` 등 사용하지 않는 중복 자원을 제거하고 `money`, `dice`, `season_coin`, `me_1` 등 핵심 재화 위주로 `resources` 섹션을 재구성합니다.

## 🎨 Mockup (mockSpec) 이식 가이드
LLE 엔진 내부에서 직접 UI를 렌더링하기 위해 `data.mockSpec` 필드를 활용합니다.

- **위치**: 주로 `choice` 노드나 행동이 발생하는 `trigger`(예: `n-roll`) 노드 내부의 `data` 객체에 위치합니다.
- **구조**:
    - `root`: 최상위 컨테이너 ID (보통 `Screen` 타입).
    - `elements`: 각 UI 컴포넌트(`VStack`, `HStack`, `Text`, `Button`, `ResourceMeter`)의 정의.
- **데이터 바인딩**: `{{pos}}`, `{{money}}`와 같이 이중 중괄호를 사용하여 JSON 내부의 변수를 UI 텍스트에 실시간으로 노출시킬 수 있습니다.
- **액션 연결**: `Button` 컴포넌트의 `on.press` 이벤트에 `executeNode` 액션과 `nodeId`를 지정하여 버튼 클릭 시 특정 노드의 로직이 실행되도록 설계합니다.

## 🎲 주사위 로직 고도화
- **개별 주사위 값 추출**: `roll = rand.d6() + rand.d6()` 대신, `d1 = rand.d6()`, `d2 = rand.d6()`, `roll = d1 + d2` 순서로 `trigger` 속성을 구성하면 UI에서 주사위 두 개의 눈금을 각각 따로 보여줄 수 있어 시각적 완성도가 높아집니다.

# 18. 리워드 중심의 보상 자동화 (V6+)

최근 타이쿤 시뮬레이션 엔진 고도화 작업(V6)을 통해 정립된 리워드 중심 설계 원칙입니다.

## 🎁 리워드 중심 설계 (Reward-Centric)
과거에는 `trigger` 노드에서 변수를 직접 계산하고 `choice` 노드에서 화면을 보여주는 복잡한 방식을 사용했으나, V6부터는 **직접적인 `reward` 노드 활용**을 권장합니다.

1. **로직 간소화**: 복잡한 수식 없이 `reward` 노드의 `resource` 연결만으로 보상 지급과 UI 피드백을 동시에 처리합니다.
2. **팝업 자동 연동**: `reward` 노드는 엔진에서 기본 보상 팝업을 제공하므로, 별도의 안내 `scene` 노드 없이도 사용자에게 보상 획득 사실을 명확히 전달할 수 있습니다.
3. **상태 전이 안정화**: 보상 획득 후 즉시 메인 루프로 복귀하는 흐름을 `reward (bottom) → gate/choice` 형태로 연결하여 시뮬레이션 중단을 방지합니다.

## 💎 자원 통합 및 좀비 노드 제거
1. **단일 재화 집중**: `gold`, `coin`, `money` 등 파편화된 자원을 `season_coin` 또는 프로젝트 표준 자원으로 통합하여 경제 밸런스 관리를 용이하게 합니다.
2. **좀비 노드(Zombie Nodes) 정리**: 플로우에 연결되어 있지 않거나 실행되지 않는 불필요한 노드는 엔진 성능 저하 및 예기치 못한 오류의 원인이 됩니다. 주기적으로 `edges`를 검토하여 고립된 노드를 삭제하세요.
3. **의존성 최소화**: 이벤트 플로우 간의 과도한 트리거 의존성을 줄이고, 노드 자체의 완결성을 높여 유지보수 효율을 극대화합니다.
