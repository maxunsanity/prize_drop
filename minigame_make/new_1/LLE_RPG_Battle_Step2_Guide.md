# LLE RPG 전투 시뮬레이션: 2단계 구현 가이드 ⚔️

본 문서는 LLE(Node-Link Engine)를 활용하여 **변수 기반의 전투 로직**과 **동적 UI(게이지 바)**를 구현하는 2단계 과정의 핵심 노하우를 정리한 학습 가이드입니다.

---

## 1. 핵심 설계 구조 (Architecture)

2단계의 목표는 하드코딩된 흐름을 벗어나 **전역 변수**를 통해 상태를 관리하고, 이를 UI와 실시간으로 연동하는 것입니다.

### 🔄 전투 루프 프로세스
1.  **변수 초기화 (`n_init`):** 플레이어와 적의 HP, 공격력, 최대 체력 등을 선언. (플레이어와 적 노드를 분리하면 관리가 용이함)
2.  **행동 선택 (`Choice`):** 공격 또는 대기 버튼이 배치된 메인 UI 화면.
3.  **데미지 산출 (`Trigger 1`):** 주사위를 굴려 이번 턴의 `damage` 값을 확정.
4.  **상태 반영 (`Trigger 2`):** 확정된 `damage`를 HP에서 차감하고, UI 연동용 `ratio` 계산.
5.  **사망 판정 (`Gate`):** HP <= 0 여부에 따라 승리/패배 또는 다음 턴으로 분기.

---

## 2. 주요 기술적 해결 방안 (Key Solutions)

### ⚠️ 데미지 계산 로직의 분리 (Atomic Calculation)
*   **문제:** 하나의 트리거 노드에서 `damage`를 계산하고 동시에 `hp = hp - damage`를 수행하면, 엔진의 동시 평가 성질 때문에 `damage`가 0이거나 이전 턴의 값이 적용되는 버그 발생.
*   **해결:** 반드시 **[데미지 굴림 트리거] ➡️ [체력 차감 트리거]**로 노드를 분리하여 순차적으로 실행해야 함.

### 📊 동적 게이지 바(Progress Bar) 연동
*   **HP 비율 변수 활용:** `player_hp_ratio = player_hp / player_max_hp` 수식을 사용하여 0~1 사이의 값을 별도 변수로 관리.
*   **UI 바인딩 (`$state`):** LLE의 `Progress` 컴포넌트에는 핸들바(`{{}}`)보다 `$state` 경로 바인딩이 더 안정적임.
    ```json
    "player-hp-bar": {
      "type": "Progress",
      "props": {
        "value": { "$state": "/player_hp_ratio" }
      }
    }
    ```

### 🔁 재시작 및 적 찾기 초기화
*   **문제:** 전투 종료 후 다시 시작할 때 HP가 마이너스 상태로 유지됨.
*   **해결:** 결과 화면의 버튼 `targetNodeId`를 `Choice` 노드가 아닌, 변수를 리셋하는 **`n_init_player` (초기화 트리거 시작점)**로 연결해야 함. 또한, 해당 경로에 실제 **엣지(Edge)**가 물리적으로 연결되어 있어야 시뮬레이션이 종료되지 않음.

---

## 3. LLE 엔진 필수 준수 사항

1.  **SDT 4대 필드 누락 금지:** 모든 상호작용 노드(`Choice`, `Action` 등)의 `sdtEffects`에는 `autonomy`, `competence`, `relatedness`, `motivation`이 모두 포함되어야 함. (2단계에서는 모두 0으로 고정)
2.  **하이픈(-) 사용 주의:** 변수명이나 ID에 하이픈을 쓰면 수식 파싱 에러가 날 수 있으므로 언더바(`_`) 권장.
3.  **마찰 점수(frictionScore):** 원활한 테스트를 위해 모든 노드의 마찰 점수를 `0`으로 설정.

---
> **Tip:** 이 가이드는 3단계인 **'데이터 테이블 연동(Entity Table)'**을 위한 기초 공사입니다. 변수 기반 로직이 안정화되어야 테이블 데이터 로딩 시 오류를 줄일 수 있습니다.
