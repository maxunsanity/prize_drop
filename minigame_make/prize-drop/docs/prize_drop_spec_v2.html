화면 구조 상세 스펙
📐 실제 게임(Monopoly GO Prize Drop) 화면 직접 분석 기준. 보드는 아케이드 머신 프레임 형태 (민트/청록색), 내부 배경은 보라색.
레이아웃 레이어 분해 (위→아래)
L1: 배경보라색 패턴 (#9b59b6 계열)
L2: 상단 HUD코인 뱃지 (좌) + x1 배수 원형 버튼 (우상단 gold 원)
L3: 아케이드 프레임민트/청록색 (#1abc9c), 상단 톱니 장식, 좌우 두꺼운 테두리, 둥근 모서리
L4: 투하 버튼 행빨간 원형 5개, 흰 역삼각형 아이콘, 프레임 상단 내부 배치
L5: 핀보드보라 배경, 흰색 구슬형 핀, 원형 트랙 + 산발 배치 혼합
L6: 중앙 장애물대형 원 (steering wheel 패턴), 좌/우 보상 원형 (1.66M / 주사위20)
L7: 측면 화살표좌우 청록색 삼각형 화살표 (벽 반사판 역할)
L8: 다이아몬드중하단 청록색 마름모 장애물
L9: 슬롯7칸 (⚡1/⚡10/⚡20/⚡100/⚡20/⚡10/⚡1), 번개 아이콘 + 숫자, 핀과 교차 배치
L10: 하단 마일스톤번개 아이콘 + 누적 단계 (80/100/120/140/800), "보상 0/8" 텍스트

핀 좌표 생성 공식 — 원형 트랙 방식
이 게임의 핀은 격자형이 아니라 중앙 원형 장애물 주변 링 + 상하단 산발 혼합 방식.
// 보드 상수 const BOARD_W = 360, BOARD_H = 540; const CENTER_X = 180, CENTER_Y = 220; // 중앙 원형 장애물 중심 // 중앙 대형 원형 장애물 const CENTER_OBSTACLE_R = 88; // 논리 단위 // 핀 링 (중앙 원 바깥 링, 9개 균등) const PIN_RING_R = 105; for (let i = 0; i < 9; i++) { const angle = (i * 40 - 90) * Math.PI / 180; x = CENTER_X + PIN_RING_R * Math.cos(angle); y = CENTER_Y + PIN_RING_R * Math.sin(angle); } // 상단 산발 핀 (4개 수동 배치) const topPins = [ { x: 80, y: 80 }, { x: 130, y: 65 }, { x: 230, y: 65 }, { x: 280, y: 80 } ]; // 하단 슬롯 구분 핀 (6개, 슬롯 경계) const SLOT_W = BOARD_W / 7; // ≈ 51.4 for (let i = 1; i <= 6; i++) { x = SLOT_W * i; y = BOARD_H - 140; // 슬롯 위 고정 } // 좌우 반사 화살표 (삼각형) leftArrow = { x: 0, y: 220, tip: 45 }; rightArrow = { x: BOARD_W, y: 220, tip: 45 }; // 다이아몬드 장애물 diamond = { cx: CENTER_X, cy: CENTER_Y + 100, size: 24, rotation: 45 };

시뮬 뱅크 구조
이전 실패 원인: 실시간 Magnet 보정 → 해결: 사전 생성 뱅크 재생 방식.
1
순수 물리 완성 (Matter.js)
원형 장애물 + 핀 링 + 좌우 반사벽 + 다이아몬드 포함한 완전한 물리 보드. Three.js 불필요.
2
simulationRunner.ts 실행
drop_position(0~4) × seed N 반복. keyframe = 핀/장애물 충돌 + 방향전환 순간만 추출.
3
JSON 저장
bank_slot{0~6}_drop{0~4}.json 35개 파일. 초기 20개/조합 (~700개), 최종 200개 (~7,000개).
4
서버 결과 → 재생
target_slot + drop_position 매칭 → bankPlayer.ts lerp 보간 재생.
