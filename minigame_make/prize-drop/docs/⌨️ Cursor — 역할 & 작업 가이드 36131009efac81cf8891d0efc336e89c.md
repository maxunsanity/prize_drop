# ⌨️ Cursor — 역할 & 작업 가이드

> 이 문서는 **Cursor의 역할과 작업 방식**을 정의한다.
> 

> 새 프로젝트 시작 시 이 내용을 Cursor에 주입한다.
> 

---

## 📌 역할 정의

Cursor는 **구조 구현 + 플레이 완성 + 최종 대조** 담당이다.

| 단계 | 내용 |
| --- | --- |
| **2단계** | [GAME.md](http://GAME.md)  • CSV 읽고 파일 구조 생성, npm 환경 세팅 |
| **3단계** | 게임 로직 완성, 빌드 검증, 커밋 |
| **5단계** | 안티그래비티와 함께 [GAME.md](http://GAME.md) Anti-Patterns 추가, Agent Audit Log 업데이트 |
| **7단계** | 소스코드와 [GAME.md](http://GAME.md) 최종 대조, 커밋 |

---

## 📖 레포를 여는 순서 (필수)

코딩을 시작할 때 반드시 아래 순서를 따른다.

1. **Markdown (`*.md`)** — 기획·인계·빌드 규칙·json-render 구조·`GAME_*.md` 등 텍스트 SSoT를 먼저 읽는다.
2. **HTML (`*.html`)** — 와이어프레임·정적 스펙 페이지가 있으면 레이아웃·카피·화면 흐름 참고용으로 읽고 구현에 반영한다.
3. **JSON** — **저장소에 해당 파일이 실제로 있을 때만** 읽는다. 없는 JSON을 **추측·생성해 근거 삼지 않는다.**

요약: **md + html로 맥락을 잡고 코드에 옮기고, json은 "있을 때만".**

## 🏗️ 2단계 — 프로젝트 기본 구조

### 작업 순서

1. Vite + TypeScript 프로젝트 생성
2. `package.json` 의존성 확정
3. **json-render 기본 골격 먼저 잡기** (가장 중요)
    - `[game]Catalog.ts` — `defineCatalog()`
    - `[game]CatalogOperationalUi.ts` — HUD 타입 등록
    - `GameJsonHud.tsx` — HUD Spec + registry
    - `hudExternalStore.ts` — HUD 상태
    - `gameControlBridge.ts` — 액션 브리지
4. `index.html` DOM 뼈대 + id 확정
5. `npm run typecheck && npm run build` 통과 확인
6. **골격만 있고 화면엔 HUD만 보이는 상태로 커밋**

### 표준 파일 구조

```
src/
  main.tsx                    # React 루트 분기
  bootstrapGame.ts            # CSV 검증, loadGameData, 게임 인스턴스 생성
  game/
    [GameName].ts             # 페이즈, Three 레이아웃, 스폰, 충돌
    loadGameData.ts
    runnerDataPaths.ts        # CSV 경로 상수 (SSoT)
    hudExternalStore.ts       # HUD $state 스토어
    gameControlBridge.ts      # 명령형 ↔ 선언형 브리지
    textCopyIds.ts
  catalog/
    [game]Catalog.ts
    [game]CatalogOperationalUi.ts
    [game]CatalogStubsAndMaterials.ts
    [game]CatalogShared.ts
  jsonRender/
    GameJsonHud.tsx
    GameLobbyCopySpec.tsx
    GameOverlayActionButtons.tsx
game_data/
  01_*.csv
docs/
  GAME.md
  CURSOR_AND_AGENT_EXPERIENCE.md
```

### 부트 순서 (반드시 따를 것)

1. `index.html` 로드 → `#game-viewport`, `#jr-hud-widgets` 등 DOM 존재
2. `src/main.tsx` 진입 → `bootstrapGame()` 먼저 호출
3. `bootstrapGame.ts`
    - `import.meta.glob`으로 CSV 원문 로드 → `runnerDataPaths` 정합 검사
    - `buildRawGameDataSheets` → `loadGameData` → `LoadedGameData`
    - `bootstrapDomTexts`로 `[data-text-id]` 줄 채움
    - `new [GameName](mount, data)` — WebGL이 `#game-viewport` 자식으로 붙음
4. `main.tsx` 후반 — 각 노드마다 `createRoot + StrictMode`
5. 페이즈 전환은 `[GameName].applyPhaseUi()`가 처리

**⚠️ `main.tsx` id와 `index.html` id가 1글자라도 어긋나면 해당 React 트리는 조용히 스킵된다. 구조 수정 시 두 파일을 세트로 본다.**

## ⚙️ 기술 스택

```
Renderer:    Three.js (OrthographicCamera 원칙)
Declarative: @json-render/core ^0.19.0
             @json-render/react ^0.19.0
Validation:  zod ^4.3.6
Language:    TypeScript
Bundler:     Vite
```

**의존성은 `dependencies`에 명시** (`@json-render/core`, `@json-render/react`, `react`, `react-dom`, `zod`, `three`)

### package.json 스크립트

| 명령 | 용도 |
| --- | --- |
| `npm run dev` | 로컬 개발 서버 |
| `npm run build` | `dist/` 프로덕션 번들 |
| `npm run build:zip` | 배포용 zip 생성 |
| `npm run typecheck` | `tsc --noEmit` — **반드시 build와 함께** |

## 🌐 json-render 구조 핵심

### 4레이어

| # | 레이어 | 역할 | 성격 |
| --- | --- | --- | --- |
| ① | Catalog | 쓸 수 있는 구성품 이름·스키마 | 선언형 |
| ② | Spec | 이번 화면 조합 주문서 | 선언형 |
| ③ | State/Bridge | `$state`·액션 브리지 | 연결 |
| ④ | Runtime | Three.js 루프·충돌·물리 | 명령형 |

### 선언형 vs 명령형 경계

```
선언형 (json-render)
  로비 카피 UI
  HUD 수치·라벨 ($state 바인딩)
  CSV 경로 (Catalog Zod literal)
  버튼 액션 (gameControlBridge 경유)
  부팅 검증 (DEV assertXxx)

명령형 (Three.js / [GameName].ts)
  게임 루프 전체
  스폰·충돌·물리
  페이즈 전환 (applyPhaseUi)
  엔티티 라이프사이클
  pushHudChrome (값 push만, 읽기는 Spec)
```

### 카탈로그 파일 4개 분리

| 파일 | 역할 | 약속 |
| --- | --- | --- |
| `[game]Catalog.ts` | 단일 관문, `defineCatalog()` 한 번 | 외부는 이 파일만 import |
| `[game]CatalogOperationalUi.ts` | 실제 화면에 그려지는 컴포넌트만 | 여기 있는 것 = 화면 후보 |
| `[game]CatalogStubsAndMaterials.ts` | CSV 경로·개념 스텁 | registry 없을 수 있음 |
| `[game]CatalogShared.ts` | `hudBindProp` 등 공통 Zod | 규칙 변경 시 이 파일부터 |

### 세트 수정 규칙 (가장 자주 깨지는 패턴)

| 수정 대상 | 반드시 동시에 바꿀 곳 |
| --- | --- |
| HUD `$state` 경로 | hudExternalStore + Spec `$state` 문자열 + pushHudChrome 키 (3곳) |
| CSV 경로 | runnerDataPaths.ts + Catalog Zod literal |
| 운영 UI 새 타입 추가 | operationalUi.ts + registry JSX 동시 패치 |
| 카탈로그 액션 이름 | actions 키 + overlayActionHandlers 키 완전 일치 |

## 🐛 반복되는 버그 패턴

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 카탈로그에만 있는데 화면에 안 보임 | registry 없음 | operationalUi + registry 동시 패치 |
| HUD 규칙 고칠 때 파편화 | $state 3곳 중 1곳만 수정 | store + Spec + push 3곳 동시 |
| 로비 글자 없음, 박스만 보임 | BOM·쉼표 파싱·폰트 폴백 누락 | 파서·폰트 점검 |
| DEV 흰화면·스크립트 중단 | Spec `visible` 필수 필드 누락 | 모든 element에 `visible` |
| 시작 버튼 화면 아래로 밀림 | 스크롤 본문 + 하단 고정 미적용 | 레이아웃 패턴 재현 |
| React 안 붙음 | `main.tsx` id ≠ `index.html` id | 두 파일 세트 확인 |
| 스텁 타입 미표시 | 의도된 스텁 | 운영이면 registry JSX 추가 |

## 📦 배포 ZIP 규칙

- 호스팅이 **ZIP 루트에 `index.html`** 을 요구한다.
- **올바름:** 압축 해제 직후 `./index.html`, `./assets/...`
- **잘못됨:** ZIP 안에 `dist/` 폴더만 있는 구조

```bash
npm run build
cd dist && zip -r ../game-upload.zip . -x "*.DS_Store" && cd ..
```
